# 项目文档自动维护

以下规则适用于主 agent 和所有层级的子 agent，在当前任务内静默执行。
技能支持原生调用时使用该接口，否则读取对应 SKILL.md 并按步骤执行。

- **每次读取项目代码或文档前**，使用 doc-context 核对相关内容的新鲜度，从项目 `.agent-docs/_index.md` 加载主模块与相关模块正文。相关 HEAD、暂存区、工作区、新增文件、文档和任务范围均未变化时复用已核验上下文；首次读取、压缩恢复或发生变化时重新核验。允许先读源码修复过时文档，核验并同步后再将文档作为事实依据。
- **每个项目写入批次后**，使用 doc-update 核对受影响模块及索引，需要时立即同步文档，再继续依赖这些内容的工作；命令失败但已产生的写入也要处理。连续相关写入可合并为一个批次，最后一次写入不能遗漏。文档自身写入只校验并更新必要派生内容，不递归启动同一维护流程。
- **每次 Git 提交前**，使用 doc-update 核对实际暂存源码和文档，展示文档差异或无需更新的具体依据，取得用户对本次审阅的明确确认后再提交；已有明确覆盖该差异的授权可复用。暂存内容变化后重新核对。日常读取、写入和同步不逐次请求确认。
- 文档库缺失时简短提示一次并继续可执行任务；缺少源码或存在冲突时保留未知项，不能伪报已同步。保留用户已有文档改动，按章节合并。
- 会话恢复、任务切换、局部工作结束和最终交付前重新对齐上述流程。委派任务时传递规则、技能路径和相关文档上下文。

技能路径：
- doc-context：`@SKILLS_ROOT@/doc-context/SKILL.md`
- doc-update：`@SKILLS_ROOT@/doc-update/SKILL.md`

规则由 AI 按 AGENTS.md 执行，不注册宿主 Hook 或 Git Hook，也不将提示反馈作为新用户消息续跑。
